# ЧАСТЬ I: ПЕРВЫЙ ВХОД И АУТЕНТИФИКАЦИЯ

## 1. АУТЕНТИФИКАЦИЯ И БЕЗОПАСНОСТЬ СЕССИЙ (P0)

### 1.1 Успешный вход с валидными данными

- [x] Перейти на `/login`
→ Форма входа отображается корректно

- [x] Ввести имя пользователя: `testuser`
→ Ввести пароль: `Test123!`
→ Нажать кнопку "Войти"

- [x] Проверить успешность аутентификации
→ HTTP 200 ответ с `access_token` и `refresh_token`
→ Токены сохранены в localStorage
→ Объект пользователя сохранен в localStorage

- [x] Проверить редирект
→ Автоматический переход на `/home` или `/w/[workspace-slug]/kb`
→ Нет ошибок в консоли браузера

### 1.2 Вход с невалидными данными

- [x] Перейти на `/login`
→ Ввести имя пользователя: `nonexistent_user`

- [x] Очистить localStorage (удалить все токены)
→ Убедиться, что `access_token` не существует

- [x] Напрямую перейти к `/w/test/kb` в браузере
→ Router guard перехватывает навигацию
→ Автоматический редирект на `/login`
→ Форма входа отображается

# ЧАСТЬ II: ОНБОРДИНГ И УПРАВЛЕНИЕ ВОРКСПЕЙСОМ

## 3. СОЗДАНИЕ И НАСТРОЙКА ВОРКСПЕЙСА (P0)

### 3.1 Создание нового воркспейса

- [x] После успешного входа перейти к селектору воркспейсов
→ Нажать кнопку "Создать воркспейс" или "+"

- [x] Заполнить форму создания
→ Ввести название воркспейса: `Тестовый Воркспейс`
→ Нажать "Создать" или "Сохранить"

- [x] Проверить создание воркспейса
→ POST запрос к `/api/workspaces/` с `{"name": "Тестовый Воркспейс"}`
→ HTTP 201 Created ответ
→ Ответ содержит: `id`, `name`, `slug` (транслитерирован), `owner` (текущий пользователь)
→ Новый воркспейс появляется в списке воркспейсов
→ Воркспейс автоматически выбран
→ Пользователь перенаправлен на `/w/[new-slug]/kb`
→ Конфигурация модулей по умолчанию инициализирована

### 3.2 Создание воркспейса с дублирующим названием

- [ ] Создать воркспейс с названием `Test Workspace`
→ Воркспейс успешно создан со slug `test-workspace`

- [ ] Попытаться создать еще один воркспейс с названием `Test Workspace`
→ POST запрос к `/api/workspaces/` успешен
→ HTTP 201 Created ответ
→ Новый воркспейс создан со slug `test-workspace-[random-7-chars]`
→ Оба воркспейса существуют с одинаковым названием но разными slug

### 3.3 Доступ к настройкам воркспейса

- [ ] Перейти к `/w/test-ws/settings` как владелец воркспейса

- [ ] Проверить загрузку настроек
→ GET запрос к `/api/workspaces/test-ws/settings/`
→ HTTP 200 OK ответ
→ Страница настроек загружается с вкладками:
   - "Основные"
   - "Модули"
   - "Участники"
   - "Настройка чата"
→ Все поля доступны для редактирования
→ Кнопка "Сохранить" видима и активна

- 🎯 Естественный путь от первого входа до продвинутых функций
- 🎯 Контекст (пользователь/воркспейс/проект) используется повторно
- 🎯 Нет необходимости возвращаться к пройденным разделам
- 🎯 Логическая последовательность действий реального пользователя

**Из детального функционала:**

- 🎯 Покрытие всех критичных модулей системы
- 🎯 Проверка API и UI взаимодействий
- 🎯 Валидация прав доступа и безопасности
- 🎯 Обработка ошибок и edge cases
- 🎯 Проверка каскадных операций и зависимостей

## ПРИМЕЧАНИЯ

**Исключено из smoke (для полного регресса):**

- ❌ Производительность и нагрузочное тестирование
- ❌ Кроссбраузерность (тестировать в одном браузере)
- ❌ Глубокое тестирование accessibility
- ❌ Все возможные комбинации фильтров
- ❌ Стресс-тесты с большими данными
- ❌ Множественные форматы файлов (достаточно PDF/DOCX)

**Рекомендации по выполнению:**

1. ✅ Выполнять в clean environment (свежая БД или reset)
2. ✅ Использовать заранее подготовленные тестовые файлы
3. ✅ При падении критичного P0 шага - остановить и сообщить
4. ✅ P1 падения - зафиксировать, но продолжить
5. ✅ Логировать время каждого раздела для оптимизации
6. ✅ Первые 3-4 раза выполнять полностью, затем выборочно (P0 всегда)

**Периодичность:**

- 📅 **P0 smoke:** После каждого релиза (обязательно)
- 📅 **P0+P1 полный:** Перед major релизами
- 📅 **Regression full:** По графику (еженедельно/ежемесячно)

**Требования к тестовым данным:**

1. **Пользователи:** Администратор, обычные пользователи (3+), разные роли
2. **Воркспейсы:** Минимум 2 с разными конфигурациями модулей
3. **Проекты:** Несколько проектов на воркспейс, разные настройки
4. **Статьи БЗ:** Корневые и вложенные (3+ уровня), различный контент
5. **Чат-сессии:** Текстовые и голосовые сообщения, разная глубина контекста
6. **Документы:** Различные типы файлов, папки, общие документы
7. **Тикеты:** Разные статусы, назначенные и неназначенные
8. **Агенты:** Настроенные со статьями БЗ, назначенные на проекты
